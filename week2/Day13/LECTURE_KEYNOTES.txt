*** This is a useful teaching moment. ***

### DESIGN PRINCIPLE:
1 agent ==> 1 responsibility

Router Agent --> only decides and routes the query.
Specialized agents --> they do the actual specialized work. --> Specialized prompts, and focused work! Also well defined boundary, easy to trace or debug!


ASK: Does, Router agent need to be stateful (use the postgres memory)?  
NO! (not usually)

However, in the Enterprize, The Router can read memory. But it still doesn't update memory.
WHy: say, the user asks a question "what is the weather there!". The router may want to extract 'there' from the history (but not in our demo usecase).




*** Advantages

Small prompts
Independent set of teams (humans) can look into the production issues!
Independent testing
Easy maintenance
Adding New specialists does not affect the other (working specialist) agents!
Easy scaling


*** Disadvantages

Router mistakes
More latency (multiple levels)
More tokens (cost - benefit tradeoff)
More workflows (can be managed using subflows)
